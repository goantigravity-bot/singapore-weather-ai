## 各轮结果

### Baseline：原始 WeatherFusionNet

```
SatelliteEncoder: Conv(1→16) → Conv(16→32) → Conv(32→64) → GAP → FC(64→128)
SensorEncoder:    LSTM(7→128) → FC(128→64)
Fusion:           Concat(192) → FC(192→64) → Dropout(0.2) → FC(64→1)
```

Val Loss=1.258, F1=51.5%。GAP 平等对待所有空间位置，周边区域的云干扰导致高误报（FP=477）。

![Baseline 评估图](model_eval_baseline.png)

---

### R1：Spatial Attention ✅

用 `SpatialAttention`（1×1 Conv + Sigmoid 注意力图）替换 `AdaptiveAvgPool2d`，让模型学习关注有云区域。

```python
class SpatialAttention(nn.Module):
    def __init__(self, in_channels):
        self.attn = nn.Sequential(nn.Conv2d(in_channels, 1, 1), nn.Sigmoid())
    def forward(self, x):
        return (x * self.attn(x)).mean(dim=[2, 3])
```

- Val Loss: 1.258 → **0.800** (📉 -36%)
- RMSE: 1.205 → **1.111** (📉 -8%)
- Recall: 97.7% → **99.6%**，FN: 6 → **1**
- 大雨预测范围：7.1mm → **12.9mm**

![R1 评估图](model_eval_r1.png)

---

### R2：加深 CNN（3→5 层）❌ 退步

CNN 从 3 层（16→32→64）加深到 5 层（16→32→64→128→128），Attention 通道从 64 升到 128。

- RMSE 略改善（1.076），但 Precision 退步（33.9%），FP 增加
- Val Loss 波动范围 0.86~**2.75**（R1 的 3 倍），训练极不稳定
- **结论：2384 样本支撑不了 352K 参数的深网络**

![R2 评估图](model_eval_r2.png)

---

### R3：Residual Block ❌ 退步

回滚到 R1 的 3 层结构，将 Conv+BN+ReLU 替换为 ResidualBlock（双层 Conv + skip connection）。

- Val Loss 1.013（退步 27%），Precision **31.1%**（所有轮最差）
- TN 仅 **5**——模型几乎把所有样本都预测为雨
- 训练时间 2063s（R1 的 3.8 倍），每 epoch ~42s
- **结论：3 层 CNN 太浅，不存在梯度消失问题，Residual 无收益**

![R3 评估图](model_eval_r3.png)

---

### R4：局部 Patch + 坐标嵌入 ✅ 全面最优

**核心改动：** 不再用整张 128×128 卫星图，而是以基站像素坐标为中心裁剪 **32×32 patch**（~14km），并在融合层加入 2 维归一化坐标特征。

```
每个样本：
├── 卫星：基站头顶 32×32 patch（从 128×128 全图裁剪）
├── 传感器：7 维时间序列（温度/降雨/湿度/PM2.5/风速/风向sin/cos）
├── 坐标：2 维归一化基站位置 (px/128, py/128)
└── 标签：下一个 10 分钟的降雨量
```

**改动文件：**
- `weather_dataset.py`：基站经纬度 → 像素映射 + patch 裁剪
- `weather_fusion_model.py`：融合层 192→194 维（+2 坐标）
- `train_direct.py` / `evaluate.py`：适配 4 元组

**结果：**
- **Precision: 35.3% → 39.2%** (✅ +4%，所有轮次最优)
- **F1: 52.1% → 55.8%** (✅ +3.7%)
- **TN: 107 → 192** (✅ +79%，误报大减)
- **FP: 479 → 394** (✅ -18%)
- 训练时间 **88s**（R1 538s 的 6 倍加速）

![R4 评估图](model_eval_r4_patch.png)

## 1.0mm 阈值全轮次对比

> 原始实验使用 0.1mm 阈值（基本算毛毛雨）。调整为 **1.0mm/10min ≈ 小到中雨** 后重新训练评估全部模型。
> ⚠️ 所有模型统一使用 32×32 patch 输入（dataset 已改为局部裁剪）。

### 阈值选择依据

| 阈值 | 真实雨样本占比 | F1 | 说明 |
|------|--------------|-----|------|
| 0.1mm | 30.3% | 46.6% | 太敏感，毛毛雨也算 |
| 0.5mm | 21.0% | 64.8% | |
| **1.0mm** | **13.0%** | **60.5%** | ✅ Precision/Recall 均衡点 |
| 5.0mm | 2.0% | 35.7% | 太严格，样本不足 |

### 对比结果（1.0mm 阈值）

| 模型 | Precision | Recall | **F1** | MAE | FP | 训练时间 | 参数量 |
|------|-----------|--------|--------|-----|-----|---------|--------|
| Baseline (GAP) | 62.2% | 50.5% | 55.7% | 0.517 | 34 | 79s | 123K |
| R1: +Attention | 57.7% | 57.7% | 57.7% | 0.494 | 47 | 80s | 123K |
| R2: +DeepCNN | 57.7% | 54.1% | 55.8% | 0.532 | 44 | 120s | 353K |
| R3: +Residual | 48.6% | 62.2% | 54.5% | 0.597 | 73 | 209s | 211K |
| **R4: Patch+Coord** | **61.8%** | **61.3%** | **61.5%** ✅ | **0.498** | **42** | **80s** | 123K |

### 分析

1. **R4 F1 最高（61.5%）**：Precision/Recall 最均衡（都在 61%+），其他模型要么偏保守（Baseline Recall 仅 50.5%）要么偏激进（R3 Precision 仅 48.6%）
2. **R3 依然最差**：Precision 48.6%，FP=73 最多，确认 Residual Block 对此任务无帮助
3. **R2 没有优势**：353K 参数但 F1 仅 55.8%，训练时间 120s，性价比最低
4. **1.0mm 阈值下所有模型 Precision 大幅提升**：从 31~39% 跳到 49~62%

---

## 阶段性结论

### ✅ R4（局部 Patch + 坐标嵌入）是当前最优

在 0.1mm 和 1.0mm 两种阈值下，R4 的 F1 均为最高。通过让模型"只看基站头顶的云"，Precision 和 Recall 实现了最佳平衡。同一时刻 60 个基站裁出不同 patch，自然产生雨/干对比样本。
